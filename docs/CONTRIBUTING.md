# 🤝 Contributing Guidelines

Thank you for your interest in contributing to the AI Council project!

## Code of Conduct

We adhere to the Contributor Covenant Code of Conduct. Please be respectful and inclusive.

## How to Contribute

1.  **Fork** the repository.
2.  Create a **feature branch**: `git checkout -b feature/your-feature-name`.
3.  Make your changes, following the coding standards.
4.  Write tests for your changes.
5.  **Run tests** locally to ensure nothing breaks.
6.  Commit with a meaningful message (see [PROCESS.md](./PROCESS.md) for commit conventions).
7.  Push your branch and open a **Pull Request** to `develop`.
8.  Await code review. Respond to feedback promptly.

## Development Setup

Follow [SETUP.md](./SETUP.md) to get a local development environment running.

## Coding Standards

- **Python**: Follow PEP 8. Use `black` formatter and `ruff` linter.
- **TypeScript**: Follow ESLint rules. Use `prettier` formatter.
- **Testing**: Aim for >80% coverage. Write meaningful assertions.

## Documentation

- Update relevant markdown files if you add or change features.
- Add docstrings to all public functions and classes (Python).
- Add JSDoc comments to React components.

## Issue Tracking

- Before starting work, check if an issue already exists.
- If not, create a new issue describing the bug/feature.
- Assign yourself to the issue to signal you're working on it.

## Review Checklist

- [ ] Code compiles without errors.
- [ ] All tests pass.
- [ ] New features have tests.
- [ ] No sensitive information (tokens, secrets) in code.
- [ ] Documentation updated.
- [ ] PR description explains the change clearly.

## Getting Help

Join our Discord / Slack (link in README) or open a GitHub Discussion.

Thank you for making AI Council better! 🚀
